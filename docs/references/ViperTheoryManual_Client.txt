1 Introduction
Viper Blast (herein Viper) is a computational fluid dynamics (CFD) based tool for simulating the airblast
environment resulting from detonation of high explosives and other sources, such as vapours and high pressure gas.
The primary purpose of Viper is to predict blast loads on structures of non-trivial geometry.
Two important aspects of Viper are the graphical user interface (GUI) and the hardware acceleration of the
numerical scheme. The GUI is designed for ease-of-use with a short learning curve and is intended for use within
a blast engineering consultancy environment where rapid project turnaround is required. Implementation of the
numerical scheme has been targeted at NVIDIA GPUs (Graphic Processing Units) in order to further reduce
analysis times and project costs.
This theory manual is intended for primarily internal use and for use by the enthusiastic customer who wants
an in-depth understanding of Viper. This will be a comprehensive and detailed guide of the physics and numerical
implementation. For specifics on how to use Viper, we refer the reader to the User Manual.
The basic functionality of Viper is based largely upon the methodology described by Rose [2001] and the Air3D
manual [Rose, 2006] and uses the AUSMDV numerical scheme as described by Wada and Liou [1994].

2.1 Equations of state
Currently, Viper has two equations of state, ideal gas and Jones-Wilkins-Lee (JWL). Each solver (see below) is
hard-coded with one of the two equations of state for efficiency.
The ideal equation of state is given by
p = (γ− 1)ρe (2.9)
whereγ = 1.4 is the (hard-coded) adiabatic index for air. The fixedγ means that the results become less accurate at

In many models and many regimes, this is an acceptable approximation.

3 Numerical methods
Viper includes several user options, including dimensionality, boundaries, equations of state, all of which can be
modified in the GUI prior to execution.
3.1 Scheme
Viper evolves the fluid equations (2.6) using the AUSMDV scheme [Wada and Liou, 1994]. This is a combination
of the AUSMD & AUSMV schemes, which themselves are based upon the Advection Upstream Splitting Method
[AUSM; Liou and Steffen, 1993]. The sheme in Viper is second order in both time and space, and is based upon
that described in section 2 of Rose [2001]; it has since been improved for enhanced stability and performance. For
example, Viper includes corrections for the Carbuncle instability and includes an option for improved stability
when evolving the blast into the far field.
1The JWL EOS is named and completely described in Lee et al. [1968], and builds upon Jones and Miller [1948] and Wilkins et al.

The general scheme effectively treats each dimension independently, and splits each dimension into two phases.
In the first phase, the conserved variables at the centre of the cells are used to calculate the conserved values at the
edge of the cells at the half-timestep. For each cell, this calculation is performed using a template of three cells,
which comprises of the the given cell and cells on either side. This yields two values at each edge, since each cell
uses a different template of three cells. Then in the second phase, edge values are first updated to produce a single
edge value, and then these new edge values are used to calculate the conserved values in the centre of the cells at
the full timestep.
3.2 Boundary conditions
In Viper, the active domain is surrounded by a layer of two boundary (or ghost) cells. These ghost cells are required
to properly calculate the values in the cells near the edge of the active domain, but are not evolved themselves.
Rather, at the end of each step, these ghost cells receive values from the neighbouring active cells depending on
the type of boundary requested. Viper includes three possible boundary conditions, which can be set individually
for each boundary at runtime.
3.2.1 Transmitting
In transmitting boundaries, the ghost cells take on the values of their neighbours. Here,
U1,j,k =U2,j,k (3.1a)
U0,j,k =U3,j,k (3.1b)
Uncx+2,j,k =Uncx+1,j,k (3.1c)
Uncx+3,j,k =Uncx+0,j,k (3.1d)
for all U, where the values on the left-hand side of the expressions are the ghost cells and the values on the
right-hand side are in the active domain; the active domain in the x direction extends from 2 to ncx+1. Similar
expressions are used in the remaining two dimensions.

3.2.3 Terminating
Terminating boundaries are designed to end the simulation once the flow has reached the desired boundary. Thus,
the fluid is only ever evolved in the active region and is only ever affected by physics within the active regions. The
conditions for terminating boundaries are below.
If a terminating boundary is set in 1D, then the simulation will terminate if ∆ ρ =|ρncx+1−ρncx| > 0.001,
where ρnxc+1 and ρncx are the final two cells in the active domain. Note that the boundary at i = 2 must be
reflecting in 1D.
If a terminating boundary is set in 2D, then the simulation will terminate if the momentum becomes non-zero
in any active cell next to the boundary, i.e., if |ρvx|i,j > 0.01 or |ρvy|i,j > 0.01 for any ( i,j )∈{ (2,j ), (ncx +
2,j ), (i, 2), (j, ncy + 2)}.
Terminating boundaries are not available in 3D.

3.3 Obstacles
Viper permits obstacles to be included within the fluid domain. Fluid cells are defined as fully inside or fully
outside of the obstacle, so the obstacle boundary is necessarily coincident with the cell edge.
3.4 Dimensionality
Viper can be run in one-, two-, and three-dimensions. Each solver is hard-coded to be run in one of these
dimensions.
One dimension assumes spherical symmetry. The left-hand boundary is defined to be reflecting and the right-
hand boundary it a termination boundary. The bomb is necessarily placed at the origin in one-dimension.
Two dimensions assume cylindrical symmetry. The axis of symmetry is defined to be reflecting while the
boundaries at the remaining three edges can be selected by the user.
Three dimensions includes no assumptions on symmetry. Currently, the user can select reflecting or transmitting
for each of the eight edges.
3.4.1 Remaps
For efficiency, the simulation can be paused and ‘remapped’ onto a higher-order grid by making use of the symmetry
of the lower-dimension simulation. For example, an air burst can be modelled in 1D until just before the blast
impacts the ground; just prior to impact, the simulation can be paused, remapped into 2D and then continued.
This remapping is explained in the User Manual, and the (manual) work flow is designed for improved efficiency
and accuracy since lower-dimensional simulations can be run at higher resolution and/or faster. No information is
lost in the process as long as the remapping occurs prior to any symmetry-breaking, and so long as the remap is
into ambient atomsphere.
3.5 Viscosity
There is no explicit viscosity, therefore turbulence can not be modelled. Artificial viscosity is not required for the
AUSMDV method, thus not included; this is a departure from other advection schemes.
3.6 Afterburn
Afterburn is discussed in Example 23 of the User Manual. From a numerical perspective, at all times and for every
cell that contains burned and/or unburned material, energy is added to the total energy of the cell. The amount
of energy is calculated upon an ‘S-curve’, which is defined by an afterburn duration and total amount of energy
to be added. Therefore, this curve dictates how much energy is to be added at each timestep by determining the
difference in energies between the next timestep and the current step. Note that by the nature of the curve, at very
small times and for times larger than the parameterised burn duration, the amount of energy added is negligible
since this difference approaches zero.

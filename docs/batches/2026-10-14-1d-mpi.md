### A1 - P1-26: where a 1D step's time goes (M) · WSL

- **TODO text:** "Measure first (OpenFOAM `-profiling` or `profiling` in controlDict, one phase
  vs two, `activation`, the JWL products update) on the P1-25 case, then decide".
- **Interpretation:** `-profiling` does not exist in OpenFOAM-9 (probe above), so ablation
  timing on case A plus a size sweep. Measurement only: no code, no default, no number changes.
- **Case:** case A as the current writer writes it: `Case1D(solver='blastfoam', charge_kg=1.0,
  material='TNT', radius_m=5.0, cell_size_m=0.001, gauge_radii=[1,2,3,4])`, `writer.write_case(
  case, case_posix='/root/p126_step_cost/base', n_procs=1)`; mesh + `setRefinedFields` once,
  then each variant is a copy with ONE `foamDictionary -set` change.
- **Pre-registered decision rule (written into the doc before the first timed run):**
  - Metric: ms per step = median of the per-step `ExecutionTime` deltas in `log.blastFoam`.
    Early window = steps 1-263 from t = 0 (the 2026-10-13 window); late window = 200 steps
    restarted from the `0.0025` state copied out of `/root/mpi1d_probe/acc_np1` (D5).
    Two repeats; if they differ by > 3 %, a third; report the median. Nothing else heavy runs.
  - **Fixed vs per-cell:** sizes dx 2 / 1 / 0.5 mm (2 500 / 5 000 / 10 000 cells), early window;
    fit ms/step = a + b·n. Fixed per-step overhead is a **lead** if a ≥ 20 % of the
    5 000-cell step. Cross-check with the probe's np 1/2/4/8 numbers (Amdahl serial fraction).
  - **Ablations** (one change each, early window unless noted): M1 `activationModel none`;
    M2 `timeIntegrator Euler` (1 stage vs RK2SSP's 2); M3 `gradSchemes default Gauss linear`
    (vs `cellMDLimited leastSquares 1.0`); M4 `interpolationSchemes default linear` (vs `cubic`);
    M5 `fluxScheme HLLC` (vs `Kurganov`); M6 one phase vs two: single-phase air on the same mesh,
    a high-pressure sphere of the charge radius, phaseProperties laid out as a single-phase
    blastFoam tutorial (`/root/blastfoam/tutorials/blastFoam/movingCone` or
    `shockTube_tabulated`, read only) - this also covers "the JWL products update";
    M7 late window as written (does the step cost move with time?). Function objects on vs off
    is already measured (112.8 vs 115.7 ms) - cite, do not rerun.
    A change is a **lead** if |Δ ms/step| ≥ 15 % of the baseline.
  - `strace -c -f` over 50 steps of the baseline: syscall share of wall time (cheap check).
  - **Done** when the leads explain ≥ 50 % of the step, or all of M1-M7 ran. If < 50 %
    is explained, "not localised" goes to the owner with the numbers (Q3), no profiler install.
- **Deliverable:** `docs/verification/1d-step-cost.md`: the rule (first), the table (variant,
  ms/step, Δ %, repeats), the a/b fit, and per lead: *numerics-neutral* (could become a task)
  or *changes the results* (owner question; what it changes; needs its own peak / impulse /
  arrival check, not run here). The 20 µs early window reaches no gauge, so no accuracy claim.
- **References:** blastFoam User Guide v6.0, sec. 10.1.7 Kurganov/Tadmor (p. 99), sec. 10.3.4
  RK2SSP (p. 103), sec. 5.6.1 activation models (p. 71), sec. 12.1 lookup tables (p. 114).

## Risks and how they are protected

- **A parallel 1D run that disagrees with serial** (cf. the ≈2 % 2D/3D peak offset): A2 is a
  hard gate before any code, with the `simple` fallback and a STOP to the owner.
- **Serial results move:** no writer change for `n_procs = 1`; `foam_golden/` byte-pinned
  (B1/B2 acceptance), `test_regression.py` last, WSL gates `test_foam_1d_vs_native.py` and
  `test_foam_kb_anchor.py` at B5.
- **Calculation code:** the rank planner is a pinned decision table (`test_foam_env.py`);
  B1 characterises the parallel tree before B2 touches anything.
- **Ingest lag** (1D writes ascii every 62.5 µs; reconstruct capped at 4 per poll,
  `runloop.py:179`): measured in B5 as app-path wall time; reported, not tuned.
- **Timing noise:** A1 runs alone, repeats, median; A2 and B5 timings never overlap A1.
- **Run corpus / WSL:** all work dirs outside `/root/blastlab_runs`; `pgrep` before each run;
  §8.2 dry run before any GUI-building suite; stop only own PIDs.
- **Untested resume path:** W3 resume reads `processor*` off disk for any dim; `test_foam_resume.py`
  runs in B2's `--for` set.

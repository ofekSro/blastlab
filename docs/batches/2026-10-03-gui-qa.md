## Interpretations (written down, not guessed)

1. **"All 63 scenarios" is a stale count.** The harness registers **78**: the 63
   of M7 (59 matrix + Q01-Q04) plus M01-M05 (OUT-1) and V01-V10 (OUT-2, OUT-4). The
   base commit's harness also has 78. GUI-10 covers all 78, plus the three new frame
   scenarios K01-K03 (T6), so **81**. (D171)
2. **"Pre-redesign baseline"** means no full Qt harness pass exists on this PC.
   `~\blastlab_qa\20260907-0108` is the Tk harness (59 scenarios, `gui/app.py`), and every
   later Qt run is a subset. The baseline is therefore recorded in 10b (T7) at
   **`0605522`**, the redesign plan commit, whose code equals `1563d65`, the last master
   before GUI-1. It runs in a `git worktree` with its own harness and the same flags as
   HEAD, F group excluded (D172).
3. **"Navigates the new frame"** means the harness reaches every screen and control
   the way a user does: it clicks the pills and the Chain link, the dimension
   segmented control, the solver chip's menu action and the case menu's Dark-mode
   action. It then checks that the click worked. Today it calls the internals
   instead (list below). The scenario logic stays.
4. **"Pass"** = every one of the 81 IDs has status `done` in one `--out` folder's
   `checkpoint.json` (none `crashed` or `killed`), with no `harness-crash` and no S1
   in `findings.jsonl`. Every other finding is one of three things: (i) also present
   at base (same scenario, category, text), (ii) an intended layout change, listed
   with its reason, or (iii) fixed in 10b or filed as F28+ with a disposition.
   Harness exit 0 is not "passed" (TODO test-matrix note).

## Constraints for both parts

- **No numerical change.** No solver, default, case key, file format, export byte,
  hand-off file or validation rule. `python blastlab/tests/test_regression.py`
  byte-identical after every task. The CRLF-modified baselines are never committed.
- **Frozen:** `blastlab/gui/` (Tk) and `customtkinter`; `core/ services/ models/
  solvers/ output/ viz3d/`; `ui/view3d_host.py`, `ui/run_controller.py`,
  `ui/viewer_link.py`; `blastlab/tests/baseline/`, `foam_fixtures/`, `foam_golden/`,
  `char_golden/`. `git diff fab0ebc..HEAD` over these is empty at the end of each
  part, so the Tk gate is not triggered. If it triggers, the nine `test_gui_*` suites
  run.
- **Committed tests:** behaviour and number assertions are never weakened. Layout pins
  may change only per plan §9, each one listed with its reason. Additions such as new
  contrast pairs or new S7 checks are fine. No new `QShortcut`: `test_ui_frame` F5
  pins exactly five.
- **8 GB home PC:** heavy suites one at a time (harness, sampler, e2e, `test_blast*`,
  any 3D solve, anything in WSL). Check free physical memory and free commit before
  each one. A `MemoryError` is treated as environment: re-run alone and record it, and
  if it repeats, run an A/B at base.
- **Harness runs** use `PYTHONIOENCODING=utf-8` (T1's deliberate F24 proof is the one
  exception, flagged in the report), `--out ~\blastlab_qa\gui10-<part>-<what>` (a
  fresh folder each time), and the harness's own settings (it writes
  `auto_cleanup: false`). Every other MainWindow uses `ensure_qapp()` /
  `private_settings()` or a temp `BLASTLAB_SETTINGS`. **CLAUDE.md §8.2 dry run first,
  expect `False`.**
- **Geometry, embedding, clipping and shortcuts are measured on the real platform**
  (CLAUDE.md §8.7): `--window`, `QT_QPA_PLATFORM` unset, Win32 through ctypes in the
  sampler. Offscreen results are never the evidence for a geometry claim.
- **Processes:** never a broad kill (F1). Stop only your own processes, by PID or
  handle. Each sampler stops its own viewer child. Before and after any WSL step,
  `wsl -d Ubuntu -- pgrep -a blastFoam` must be empty.
- **Git:** stage by explicit path only. Never stage `docs/references/INDEX.md`,
  `docs/references/ViperTheoryManual_Client.pdf`,
  `docs/references/ViperTheoryManual_Client.txt`, `docs/references/viper_vtk_sample/`,

  (GUI-10)`, `tests: … (GUI-10)`, `fix(verify): … (GUI-10)`. Never push.
- Every repo edit goes through Edit / Write, never PowerShell strings (CLAUDE.md §8.1).
  The Markdown cap of 1000 lines applies to every file written.

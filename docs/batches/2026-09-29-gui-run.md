**Goal in one sentence:** rebuild the Qt Run tab as the board's 02 Run screen.
It has three columns (controls · centre · live gauges), a progress strip with
elapsed time and ETA, a Log · Messages · Earlier runs dock that keeps every
run's log, a Stop that asks for confirmation after 30 s, a live-gauge list sorted
by Z, and a finish banner with a Windows notification. No number, default, case
key, file format or controller protocol changes anywhere.

**Spec:** [docs/gui-redesign-plan.md](../gui-redesign-plan.md) §6 (02 Run), §4
(title, keys), §9 (rules), §10 (GUI-6 acceptance), §11 (risks: the embedded
viewer after GUI-6).

`Run_Finished.dc.html` (identical HTML, `state` defaults to `finished`). Read the

**UX findings answered:** UX-7 (Stop key and its confirmation), UX-18 (Messages

**Findings from earlier batches that bind this one:**
- The app-wide QSS rule `QWidget { font-family; font-size }` overrides a QFont
  family or size set in code (D6). Set fonts through per-widget style sheets or
  `#objectName` QSS rules, as `components.py` does.
- A QSS `min-height: 0px` silently beats `setFixedHeight` (D41). Pin every
  board height in the QSS: Stop / Run again 48 px, 3D square 56 × 48, Exec
  buttons 32, list rows 40, dock tabs 38-40.
- `ui.testing.ensure_qapp()` forces the offscreen platform unless
  `offscreen=False` is passed or `QT_QPA_PLATFORM` is already set. Use
  `ensure_qapp(offscreen=False)` for every geometry measurement and screenshot.
- The embedded 3D viewer is a real Win32 child of its card (`_e2e_ui_embed.py`
  explains why). Any sibling that appears, disappears or resizes above it moves
  it, so re-measure it (CLAUDE.md §8.7).

#### T2 · Progress strip, the run clock, elapsed and ETA — size M

**Files:** new `blastlab/ui/run_clock.py` (toolkit-free), `blastlab/ui/run_panel.py`,
`blastlab/ui/app.py` (drive the clock from `on_running`, `on_run_started`,
`on_paused`, `_set_hd13_busy`), `blastlab/tests/test_ui_run_screen.py` (R2),
`blastlab/tests/test_ui_run_panel.py` (the U4 access path only, see
"Committed assertions").

- `run_clock.RunClock(now=time.monotonic)`:
  - `start()` starts a run and `stage()` starts a stage. `hold(bool)` pauses and
    resumes the count.
  - `run_s()` is the **run time**: wall time since `start()` with held time
    excluded. `stage_s()` is the same for the current stage.
  - `eta_s(frac)` returns `stage_s() * (1 - frac) / frac` when `frac >= 0.05`
    and the clock is not held, else `None`. That is plan §6's linear
    extrapolation, shown only after 5 %.
  - `stop()` freezes the clock. `now` is injectable: that is the fake clock of
    R2 and R3.
- `fmt_duration(s)`: `12 s`, `4 min 18 s`, `1 h 02 min`. Pure.
- The **Progress tile** (`accent_bg` background) holds the `PROGRESS` caps, the
  percent (`78 %`, Space Grotesk 22) and the existing `progress` QProgressBar
  moved into it. Keep range 0..1000, the same values and the same
  `set_busy` indeterminate range `(0, 0)`: the HD 1.3 golden pins it. Under it
  goes the **time line**:
  - Running, below 5 %: `12 s elapsed`.
  - Running from 5 %: `4 min 18 s elapsed · about 1 min 15 s left`.
  - Held: `held at step N · 1 min 2 s elapsed`, with no ETA.
  - Finished: `Done in 5 min 31 s`. T7 appends how the run ended.
  - Stopped: `Stopped after 1 min 2 s`.
  - HD 1.3 busy: `HD 1.3 assessment · 12 s elapsed`, with an indeterminate bar
    and the percent shown as `—` (plan §6, last bullet; no Cancel is added).
- A 1 s QTimer, running only while a run or HD 1.3 is live, refreshes the time
  line, so the elapsed time ticks through a blastFoam cold start that sends no
  progress for minutes. It stops when idle. Harness B02 measures idle CPU.
- **Tiles:**
  - TIME holds the `t [ms]` value with the caption `simulated`.
  - STEP holds the step value with the caption `dt <dt> s`.
  - P MAX holds the `p max [kPa]` value with the caption `in the field now`.
  - CELLS (AMR runs only) keeps today's rule and tooltip.
  They are `StatTile`s, and the strip wraps to two rows below the width where one
  row fits: Progress on the first row, the tiles on the second (the pattern of
  D29).
- **`chip_texts()` keeps its five keys and returns byte-identical value
  strings.** The keys are `step`, `t [ms]`, `dt [s]`, `p max [kPa]` and
  `cells`, with values such as `'1234'`, `'1.500'`, `'2.50e-07'` and
  `'345.7'`. `_e2e_ui_live_sync` and the harness read them. The board's
  `11,284` and `4.1e-7` are sample formatting and are not adopted; that is a
  decision row.
- Clock sources in `app.py`:
  - `on_running(True)` calls `start()` and `on_running(False)` calls `stop()`.
  - `on_run_started` calls `stage()` (a chain stage) and `on_paused(p)` calls
    `hold(p)`.
  - A `set_running(True, paused=True)` start begins held.
  - `_set_hd13_busy(True/False)` calls `start()` / `stop()`.
  The **RunController is not changed**: its handler protocol is pinned by
  `test_ui_drain.py`'s stub handlers.

## Risks

1. **Numbers on screen.** The column is the first place the GUI shows peaks
   *while* a run goes, and the notification the first place it shows a peak
   outside the app.
   - Guard: every number comes from `output.gauge_summary.summarize_trace` /
     `summarize_gauges` and `scaled_distance`.
   - R5 and R6 compare against those functions called in the test, never
     against literals.
   - The only arithmetic added is the display conversion `(p - P_AIR) / 1e3`,
     which is the one `LiveGaugePane` already does, and the ETA extrapolation
     (display only).
   - `test_regression.py` runs after every commit. No solver or `output/` file
     is edited.
2. **Collection cost** (T6): always-on collection on the Run screen copies the
   gauge series on every live frame (native) or re-reads blastProbes once a
   second (foam, `GAUGE_LIVE_S`). Guard: the pre-registered rule in T9, a ratio
   of 1.10 or less with identical results. If it fails, collect only while the
   column is visible *and* throttle the GUI side to 2 Hz. Record that as a
   decision; do not touch the solvers.
3. **The embedded 3D viewer** now sits under a strip that wraps and over a dock,
   and in 6b under a banner that appears at run end. CLAUDE.md §8.7 says four
   earlier explanations were wrong. Guard: the Win32 sampler, twice (T5 and T9),
   0 ms pre-registered, and real platform only.
4. **Modal hazards for unattended drivers.** The Stop dialog goes through the
   *already patched* `dialogs.ask_yes_no`, which the harness records and answers
   True by default. The notification goes through `dialogs.notify_desktop`,
   which the harness recorder gets. No new unpatched modal is added.
5. **Stop-key behaviour.** F5 of `test_ui_frame` pins that Shift+Esc reaches
   `ctrl.stop` with no run live. So `_stop` must *not* gain an early `if not
   running: return`. It only adds the ask, after 30 s, while running.
6. **Height at 1100 × 720.** The strip (possibly two rows), the view toolbar,
   the view and the dock must fit in about 610 px, and a banner takes about 60
   more at the end. Guard: P1 and the U15 replacement (view ≥ 240 px). The dock
   gives way to about 110 px first.
7. **Windows focus rules.** `activateWindow()` from a toast click may only flash
   the taskbar (the foreground lock). That is acceptable. Report what happens on
   this machine; do not work around it with Win32 calls.
8. **Session safety.** Run the CLAUDE.md §8.2 dry run before building any
   MainWindow. Use throwaway `BLASTLAB_SETTINGS` everywhere (`private_settings()`
   / `ensure_qapp()`), and `use_model()` for every real run, so no model folder

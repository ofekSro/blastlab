## Interpretations taken (write-downs, not guesses)

1. **"Split FieldForm's PLACEMENT, not its parsing" (plan §11, restated by the
   owner for this batch):** `FieldForm` stays one instance per dimension;
   `v`, `points`, `get_case`, `set_case`, `apply_scope`, `mark_fields`,
   `on_field` and the Var fan-out contract do not change. What changes is only
   *where the built cards are laid*: a new placement mode puts each node's cards
   on a page of a properties stack instead of the two columns. The existing
   two-column placement **stays the default**, because `ChainPanel` builds
   `CaseForm(d)` standalone (chain_panel.py:133) and so do `test_ui_setup_form`
   and the harness — GUI-9 rebuilds the chain editor later, not this batch.
2. **"Round trips byte-identically" (plan §10)** means *as today*:
   `test_char_case_json.py` pins the exact bytes the two committed cases
   (`tests/cases/native_2d_small.json`, `native_3d_small.json`) become after
   load→save, **including** the known AMR-defaults substitution (P1-8,
   pre-existing, pinned by test_ui_setup_form S3). Do not fix P1-8 here.
3. **"Units in a suffix inside the input where the engine allows it" (§5.2,
   UX-11):** the engine renders plain `QLineEdit`s and every caption string with
   its `[unit]` is pinned by tests (S8, AXISYM_LABELS). The engine therefore
   does *not* allow it today; keep units in the captions for 5a and record the
   deferral as a decision row with this reasoning. Do not rewrite pinned
   captions in this batch.
4. **Node numbering is fixed 01–07** per the plan's table even when a node is
   hidden (native 1D has no 04 Structure, no 05 Trigger, no VTK in 07's second
   card): a hidden node disappears, the others keep their numbers. Record as a
   decision row.
5. **0D (HD 1.3)** keeps its own cards; its tree is "one node per visible card"
   (plan §5.1), numbered in build order, `HIDDEN_CARDS_0` stays hidden. No
   Derived card, no trigger switch, no Z anywhere on 0D.

## Risks

1. **The FieldForm reparenting is the riskiest change of the whole track**
   (plan §11). The file's own comments document three traps already paid for:
   the QStackedWidget minimum is the largest of *all* pages visible or not;
   a card re-added to a layout under a visible parent un-hides itself; a
   hidden page keeps stale cached layout minimums. Protect with the parity
   clipping sweep (P1/P1b) run after **every** task, and with S6's
   scope-round-trip as the characterisation test that placement never touches
   values or visibility state.
2. **No numerical surface is touched, but two GUI numbers are shown**
   (Z, and `r_exp` in the Derived card). Guard: Z is a new display-only helper
   pinned by its own test (3.31 / 2.99 / 1.00 / None cases) before any screen
   shows it; the charge radius is *read from* `ValidationReport.r_exp`, never
   recomputed — an assert-against-the-report test, not a literal. Nothing is
   exported, so no golden can move; `test_regression.py` after every commit
   proves it.
3. **The 3D preview host moves parents** — CLAUDE.md §8.7: every stand-in
   reproduction of this widget has been wrong; measure with ctypes Win32 on
   the real platform, report the longest wrong-place stretch.
4. **The app-wide QSS font rule** (decision D6) silently overrides programmatic
   QFont: node headings, tree numbers and mono summaries need per-widget style
   sheets or object-name rules, as `components.py` already does.
5. **Trigger switch vs. saved cases**: the one place 5a touches how a case
   value is *entered*. The both-ways equality test (switch path ≡ old int
   field path, `vars()` compare) plus `test_char_case_json` is the
   characterisation pair.
6. **Session safety**: before anything builds a MainWindow, run the CLAUDE.md
   §8.2 dry run (`env.cleanup_plan`; expect `<repo>\settings.json False` and
   an empty plan) — every GUI build path can reach the run corpus.

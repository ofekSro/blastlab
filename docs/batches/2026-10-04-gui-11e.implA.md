## A1 - F42: gauge labels after a dropped gauge - DONE

`output/gauge_summary.gauge_labels` used to pair the entered gauges with the solver's
points by index. Now, when there are fewer points than entered gauges, each point is
paired with its nearest entered gauge. The match is in the same dimension, by squared
distance, greedy in point order, and each entered gauge is used once (private
`_nearest_entered`). The label prints that gauge's **entered number** and entered
position, the way the screens number it (D201). With points >= entered gauges the
pairing stays by index, so a run without a drop is byte-identical.

- **P1:** if the pairing leaves a point without an entered gauge (possible only with
  mixed-dimension entries), every label falls back to the plain `G<k> (point) m`.
- **P4:** the helper stays private in `output/`.
- Recorded as decision row D230; F42 has an outcome note.

## A2 - F44: the drop warning uses each solver's real rule - DONE

`services/validation._gauge_drop_rule` predicts the drop without running any solver
code.

- **Native:** the solver keeps the nearest cell centre on each axis. A gauge is dropped
  when that centre lies inside a raw box, with the faces counting as inside
  (`core/bc.solid_mask_*`). The grid is the solver's own: `case.cell_size_m`, or the
  charge auto-refine (`refine.effective_dx`, `solver2d.py` 163-175 / `solver3d.py`
  186-203), except for 3D `smear`. It is laid out by `core.grid._faces_shared`. It is
  never `ctx.dx`, the validator's own refined size, which differs from the solver's.
- **blastFoam:** a gauge is dropped when it lies inside a box snapped outward by
  `refine.snap_obstacles(boxes, dx_base)`, faces counting as inside (`writer.py`
  495-501 / 555-562). `dx_base` comes from the plan, or from `plan_levels`' base cell
  when validation made no plan.
- **P2 (wording):** a gauge strictly inside a box keeps `... inside an obstacle - will
  be dropped`; one dropped on or just outside a face reads `... on an obstacle face -
  will be dropped`.
- **P3:** a native profile start uses `case.cell_size_m`.
- Recorded as decision row D231; F44 has an outcome note.

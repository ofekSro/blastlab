## Suspected issues (noticed, not changed)

1. **The progress fraction runs ahead of the run.** On the sample case the
   strip reads `100 %` from about 2.2 ms of 6.1 ms simulated. At 60 % it
   reads `… about 25 s left` with about 150 s to go. `frac` is the
   solver's front / stop-distance estimate, so T2's linear ETA is up to
   about 5× optimistic here, and `about 0 s left` shows for minutes. That
   is solver progress semantics (`Progress.frac`), not the clock.
2. **F13:** the viewer's resize lag of 22-49 ms predates 6b. Also, 6a's
   report claimed 0 ms for resizes, which this sampler does not reproduce
   at 6a's own HEAD.
3. **F9 is wider than recorded.** An Initialise after a finished native 3D
   run also shows no viewer window. That is why "the banner goes" could
   only be measured through `banner.hide()` with the viewer visible, which
   is the same call the next start makes.
4. **The view at 1100 × 720 with the banner up is 201 px tall** (U15 pins
   240 for the idle layout; risk 6 foresaw it). The banner is two lines by
   design (D70).
5. **The first line of the banner is short at 1100 × 720.** The stop
   reason is cut (`Result ready: wall_A · shock a…`). The tooltip and the
   time line above carry it.
6. **The toast is headed "Python 3.12"** from a test process. The app sets
   AUMID `blastlab`, but no Start-menu shortcut registers it, so Windows
   may still show the raw id. Not checked from `python -m blastlab`.
7. **This PC's memory.** Commit charge sat at 0.4-2.2 GB free all session.

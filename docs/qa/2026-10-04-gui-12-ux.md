## 2. User flows (as written)

**F1 - Setup, a gauge in or on a wall.** The user enters gauges in the Gauges tree. The
table (`setup_panel.py:847-853`) shows `G<n>`, coordinates at 2 decimals, R, Z and Where
(`scaled_distance.where_text`, `:212-225`: `inside Wall 1` / `on the face of Wall 1`
when the gap rounds to 0 cm / `N cm in front of|behind Wall 1`). Checks shows
`Gauge (x, y) inside Wall i - will be dropped`, or `... on the face of Wall i - will be
dropped` (`validation.py:1569-1577`). Which wall is named comes from the solver's own
drop rule. The inside/face split is the open-box test. A gauge outside the domain gives
`Gauge (x, y) outside domain - will be dropped` (`:1565`). These are warnings and do not
block Run.

**F2 - Chain, default 1D -> 2D -> 3D.** The seed is 1D R 10 m, 2D 4 x 4 m with Burst y
2.0, and 3D 1.5 x 1.5 x 1.5 m. Both card 2 (S2-1 reach) and card 3 (F45) show
`● 1 warning`. Stage 3's Checks gives `The 2D stage's burst is at z 2.0 m, above this
stage's 1.5 m height: the remapped field misses the burst. Raise this stage's height
above 2.0 m.` (`chain_route.py:222-238`). Run chain stays enabled (D200). The fields
involved are labelled `Burst y [m]` on the 2D form (`setup_spec.py:501`) and `Lz [m]`
on the 3D form (`:464`). The stage-3 centre hint says `domain is 1.5 × 1.5 × 1.5 m,
burst at z 2.0 m (from the 2D profile)` (`:428-449`). The tree's `Domain & mesh` row
stays ✓ (screenshot).

**F3 - Run, a gauge dropped by the solver.** Live rows are labelled with the entered
number (`run_gauges._numbering`, `:203-231`; pairing `pair_in_order`). The caption
(`:868-872`, muted, word-wrapped) reads `4 gauges, sorted by Z. Click a row to enlarge
it. G2 dropped by the solver (inside Wall 1).` Its reason comes from
`_drop_reason` (`:150-181`), a geometric re-derivation that shares only the wording
helper with validation. The finish notification maps the highest peak to the entered
label (`app.py:1440-1462`).

**F4 - Results, Gauges view and export.** Table/readout labels come from
`labels_and_dropped` (`results_gauges.py:179-194`). That function rebuilds a case from
meta and returns `{}` (plain numbering) when any of `charge`, `charge_center`,
`from_profile`, `gauges` (2D: `geometry`) is missing. The caption puts the drop note
first (`:482-484`, elided, full text in the tooltip). The exported grid
(`plots.figure_gauges_nd`, `:390-403`) titles each panel `Gauge <entered n>  (cell x,
cell y) m` through `entered_numbers`, which reads only `meta['gauges']` and has no
tolerance. The figure itself does not mention a drop.

**F5 - Results, 1D Field.** The canvas title is the short `1D spherical · 1.0 kg TNT ·
JWL`. Hovering anywhere on the canvas shows `Exports use the full title: 1D Spherical
Blast - 1.0 kg TNT - EOS: JWL[ - extra]` (`results_fields.py:434-437`). 2D/3D views
clear the tooltip (`:439`, `:451`).

## 3. Findings

Nothing in this batch touches threading or data loss. No finding is high on the
threading/data-loss rule, so the top severity here is medium.

1. **Medium - Chain, default seed warns on two of three cards.** `test_ui_chain_screen.py:530-570`
   pins it, decision row 2 accepts it, and the screenshot confirms it. A new user's
   first chain opens with `1 warning` on cards 2 and 3 before they have typed anything.
   That teaches them that warnings are normal and can be ignored, which works against
   every real F44/F45 warning. *Fix (owner decision, reopens row 2):* seed the 3D stage at
   `Lz` >= 2D `Ly` (4 m, which the `:741` check already treats as silent) and the 1D
   radius inside stage 2. Alternatively, mark seeded-but-untouched warnings as "example
   values" until the user edits a stage.
2. **Medium - Chain stage 3, F45 text names fields the forms do not have.**
   `chain_route.py:236-238`. The 2D form calls the burst height `Burst y [m]`; the 3D
   form calls the height `Lz [m]`. The warning says "burst is at z" and "this stage's
   height". The user has to translate both before they can act. *Fix:* `Stage 2's Burst
   y (2.0 m) is at or above this stage's Lz (1.5 m): the 3D box cuts the 2D field off
   above 1.5 m, burst included. Raise Lz to at least 4.0 m (stage 2's Ly) or lower
   stage 2's Burst y.` `in_text`'s `burst height, z` (`:413`) has the same y/z mismatch.
3. **Medium - Chain stage 3, the suggested fix still truncates the field.** `:238`.
   "Raise ... above 2.0 m" accepts `Lz` = 2.1 m, and that still cuts the whole upper half
   of the 2D field (the remap fills z > Lz with nothing and z above the 2D extent with
   ambient air, `core/profiles.py:259-281`). The threshold only says when the warning
   stops firing; it is not a recommended value. The only lever offered is on stage 3,
   and card 2, where Burst y lives, stays silent. *Fix:* recommend `Lz >= stage 2's Ly`
   (or `>= zb +` the 2D shock radius at hand-off). Show a short pointer on card 2 as a
   note. *Engineering question for the owner:* is "at or above Lz" the right trigger, or
   should it be "Lz below the 2D Ly"?
4. **Medium - Setup/Chain Checks, the drop warning identifies the gauge by a raw tuple.**
   `validation.py:1565,1575`. `Gauge (1.2, 0.3) inside Wall 1 - will be dropped`:
   there is no `G` number, no unit, and the formatting is Python `repr`, so a computed
   value can print as `1.2000000000000002`. The table beside it (`setup_panel.py:848`),
   Run and Results all say `G2` with 2-decimal coordinates. The user has to match
   coordinates by eye. *Fix:* the loop already has the index, so use `G2 (1.20, 0.30) m
   inside Wall 1 - will be dropped`. This edits `test_case_validate` strings and needs
   the owner gate.
5. **Medium - Results export, a dropped gauge disappears silently from the PNG.**
   `plots.py:390-403`. After A3 the panels read `Gauge 1`, `Gauge 4`, `Gauge 5`, which
   is correct. But the figure, which goes into reports, does not say why 2 and 3 are
   missing, while the screen caption does (`results_gauges.py:482`). *Fix:* add a
   figure footnote from the same `dropped_text` wording (`G2, G3 dropped by the solver
   (inside Wall 1)`), only when there is a drop, so the no-drop bytes are unchanged
   (F42 rule).
6. **Low - Setup, Where and Checks can describe the same gauge differently.**
   `scaled_distance.py:222-225` vs `validation.py:1574-1576`. Where says `on the face`
   only when the gap rounds to 0 cm. The drop warning says `on the face of Wall 1` for
   any gauge whose snapped cell is solid, up to half a cell or more off the face. One row
   can read `4 cm in front of Wall 1` while Checks says `on the face of Wall 1 - will be
   dropped`. The reverse also happens: Where says `on the face` for a native gauge the
   solver keeps (D201). *Fix:* word the face case as `within a cell of Wall 1's face`,
   or add `(dropped)` to the Where cell from the same drop rule.
7. **Low - Run vs Setup, the wall named for a drop can differ.** `run_gauges.py:165-173`
   takes the first box within one cell (closed + tolerance). Validation takes the box of
   the solver's snapped cell. With adjoining or overlapping walls, Run can say `Wall 1`
   where Setup said `Wall 2`. A4 shares only the wording (`gauge_drop_reason`), not the
   rule. Minor wording drift too: `outside domain` (`validation.py:1565`) vs `outside
   the domain` (`run_gauges.py:178`). *Fix:* export a public `drop_wall(case, pt)` from
   `services/validation.py` and call it from `_drop_reason`. Fold the domain wording into
   `gauge_drop_reason`.
8. **Low - Results, screen and export labels come from two pairing inputs.**
   `results_gauges.py:179-194` + `scaled_distance.py:67-79` need five meta keys and
   use `tol = meta['dx']`. `gauge_summary.entered_numbers` (`:123-137`) needs only
   `meta['gauges']` and has no tolerance. Current native/foam metas carry all of them,
   but an older or post-mortem result missing one would show `G1 G2 G3` on screen and
   `Gauge 1 4 5` in its PNG. *Fix:* when `case_from_meta` is None, fall back to
   `entered_numbers` for the labels.
9. **Low - Results export, panel titles use a different style and position from every
   other surface.** `plots.py:402-403`: `Gauge 4  (1.25, 0.30) m` gives the snapped
   cell at 2 decimals with no "cell" marker. The Summary table and CSV say `G4 (1.200,
   0.300) -> cell (1.250, 0.300) m` (`gauge_summary.py:113-118`), and Setup shows the
   entered `1.20, 0.30`. A reader can take the export as a typo of their input (the same
   problem QA-33 fixed in the table). *Fix:* in the drop case at least (no-drop bytes
   stay pinned), show `G4 (1.20, 0.30) m → cell (1.25, 0.30)`.
10. **Low - Results 1D Field, the export-title hint is a canvas-wide tooltip.**
    `results_fields.py:437`. It appears wherever the cursor rests over the plot,
    including while reading curves, and it is invisible to a user who goes straight to
    Export. *Fix:* put the same text on the Export column's PNG/PDF buttons, or show it
    as the tooltip of the title only. Keep it built from the builder's title as now.
11. **Low - Run, the drop note has the least emphasis on the card.** `run_gauges.py:870-872,925`.
    It is appended after "Click a row to enlarge it." in the same muted 12.5 px style.
    Results puts the note first for the same reason (`results_gauges.py:480-484`).
    *Fix:* put the note first, in the warn colour, as Results does.
12. **Low - Chain stage 3, the warning is not tied to the tree row that fixes it.**
    Screenshot: `02 Domain & mesh ✓` while Checks warns about the height. *Fix:* mark
    `Domain & mesh` with the warn glyph when the F45 line is present. Make the Checks
    line a link that opens the row and focuses `Lz`.
13. **Low - The `above` wording is used when the values are equal.** `chain_route.py:234-236`
    fires at `zb >= Lz` but says "above". Covered by the rewording in finding 2.

Checked and fine: F45 text is unclipped at 1100 x 720 (screenshot). The B3 tooltip is
cleared on 2D/3D. The finish notification and the Run/Results `G<n>` labels share
`numbering`. A3 leaves the no-drop titles byte-identical.

```
+ Stage tree ----------+ Centre ------------------------+ Hand-off / Checks ------+
| 01 Initial  ✓        | 3D: no preview.                | HAND-OFF IN             |
| 02 Domain   ⚠ ← F45  | Domain 1.5×1.5×1.5 m           |  from 2D: Burst y 2.0 m |

| ...                  | [mini side view: box + burst]  | CHECKS                  |
| [Stage OK·1 warning] |                                | ⚠ Stage 2's Burst y ... |
+----------------------+--------------------------------+  [Go to Lz] [Go to st.2]|
                                                         +-------------------------+
```

Warnings point at the tree row and the field. The centre hint marks the out-of-box value
instead of stating it neutrally. A 2D side sketch (box outline + burst dot) would make
F45 obvious without reading any text.
